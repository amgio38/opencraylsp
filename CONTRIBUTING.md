# Contributing

Thanks for helping improve `opencraylspd`. This project is Rust (edition 2024, MSRV
1.89) and builds with Cargo.

## Layout

| Crate | What it owns |
| --- | --- |
| `opencraylsp-proto` | Wire types (daemon protocol, `ToolDef`, `ToolOutput`, `StatusReport`). Only the contract owner changes this. |
| `opencraylsp-core` | Transport, instances, document sync, config, root discovery, the pool, the backend trait. |
| `opencraylsp-tools` | The `lsp_*` catalogue, argument schemas, symbol resolution, formatting. |
| `opencraylsp-client` | Connecting to `opencraylspd`, starting it, reconnecting; the `DaemonHost`. |
| `opencraylsp-mcp` | The MCP stdio server binary and its `--embedded` mode. |
| `opencraylspd` | The daemon binary (`src/server/**`) and its CLI (`src/cli/**`). |
| `opencraylspd-e2e` | End-to-end tests: a real `opencraylspd`, a real `opencraylsp-mcp`, and a fake language server. |

Dependencies point one way:

```
opencraylsp-proto <- opencraylsp-core <- opencraylsp-tools <- opencraylspd, opencraylsp-mcp[embedded]
opencraylsp-proto <- opencraylsp-client <- opencraylsp-mcp, opencraylspd(cli)
```

`opencraylsp-core` and `opencraylsp-tools` must not depend on `opencraylsp-client`, `opencraylsp-mcp` or `opencraylspd`.
A dependency must come from crates.io or from this workspace: a `path`
dependency may only point at another crate in this workspace, and a `git`
dependency is never allowed. `scripts/check-layering.sh` enforces this; run it
with `make layering` (it can also point at a fixture tree with `--root DIR`).

For how the pieces fit together and why, read
[docs/ARCHITECTURE.md](docs/ARCHITECTURE.md); the rules above are also checked
by `scripts/check-layering.test.sh`.

## Building and testing

```sh
make check          # cargo check --workspace --all-targets
make fmt-check      # cargo fmt --all -- --check
make clippy         # cargo clippy --workspace --all-targets -- -D warnings
make test           # cargo test --workspace
make layering       # dependency-direction check
make docs-check     # docs links / language / TOOLS.md sync
make ci             # all of the above
make preflight      # what CI runs, in CI order: run it before every push (docs/RELEASING.md)
```

`make release-static` builds self-contained `dist/opencraylspd` and `dist/opencraylsp-mcp`. It
requires the `x86_64-unknown-linux-musl` target and does not install it for you:

```sh
rustup target add x86_64-unknown-linux-musl
```

The machine this project is developed on is shared, so builds are throttled with
`-j 14` (override with `JOBS=...`). A plain `make test` runs the whole workspace.

## Test conventions

- **Never touch the real home or the default socket.** Tests use a temporary
  directory for the socket, config, workspace and `HOME`, and remove the `XDG_*`
  variables from spawned processes.
- **No leftover processes.** Address processes by pid; `pkill -f` and `pgrep -f`
  are forbidden. A test that starts a daemon or language server kills it and
  asserts its pid is gone.
- **Do not fix flakiness with sleeps.** Poll a condition with a timeout.
- **Fake language servers must not be more permissive than the real thing.** A
  double that reads from disk when a real server would answer from the text the
  client synced lets a missing-sync bug pass; `opencraylspd-e2e`'s `fake-lsp` keeps the
  synced document and answers from it for exactly this reason.
- **Prove a test can fail.** When adding a test for a behaviour, break the
  behaviour temporarily and check the test goes red, then restore it.

## Submitting changes

- Keep changes scoped to one area; update the docs a change affects
  (`docs/`, `README.md`, and `docs/TOOLS.md` for the tool catalogue, which is
  generated by `scripts/gen-tools-doc.sh`).
- Run `make ci` before sending a change.
- Write commit messages that say what changed and why.
